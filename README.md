# 桥梁健康智能监测与全寿命健康运维系统

本项目是桥梁健康监测演示系统，包含原生 HTML、CSS、JavaScript 前端和 FastAPI 后端。当前演示工程为巨力大桥、乐凯大街转体斜拉桥。

前端默认进入数据大屏。“项目总览”和大屏 GIS 入口已移除。界面中的规范、安全体系和运维流程用于方案展示，项目本身尚未提供生产环境认证或真实传感器采集能力。

## 快速启动

需要 Python 3.10 或更新版本。前端运行无需 Node.js 或前端构建步骤。

在项目根目录打开第一个终端，启动前端静态服务。

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

在第二个终端中，从项目根目录执行以下命令。

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run.py
```

Windows PowerShell 中，虚拟环境激活命令为 `.\.venv\Scripts\Activate.ps1`。

- 前端地址为 [http://127.0.0.1:8080/](http://127.0.0.1:8080/)。
- 后端接口文档为 [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。
- 后端详细配置和接口说明见 [backend/README.md](backend/README.md)。

目前前端登录和系统设置请求固定访问 `http://127.0.0.1:8000`，远程部署时需要调整 `js/auth-demo.js` 和 `js/settings.js` 中的地址，并配置 HTTPS、反向代理和允许的来源。

## 登录与权限

首次初始化数据库会创建两个演示账号。

- 管理员账号为 `admin`，初始密码为 `admin123`。
- 工程师账号为 `engineer`，初始密码为 `engineer123`。
- 管理员可在系统设置中新增账号，并指定管理员、工程师或只读用户角色。

后端正常运行时，登录通过后端校验。身份和 JWT 保存在当前标签页的 `sessionStorage`。后端无法连接时，前端仍可使用内置演示账号浏览演示页面，该身份无法调用受保护的系统设置接口。

系统设置中的人员和 AI 配置由后端管理员权限控制。项目管理页面的角色限制仍属于前端演示。其他页面的演示操作尚未全部接入统一的后端权限管理。

令牌过期或后端签名密钥变化后，需要退出并重新登录。默认账号仅供本地演示。

## 当前功能

### 数据大屏

- 深蓝色城市鸟瞰桥梁场景，巨力大桥采用弧形桥塔，乐凯大桥采用双塔及桥下铁路场景。
- 每座桥显示 16 个测点，覆盖桥塔、拉索、主梁、桥墩、支座和引桥。
- 悬停查看测点信息，点击打开对应 SHM 设备档案，支持定位到设备台账。
- 展示桥梁档案、健康评分、关键监测指标、预警、测点分布、趋势和设备运行概况。
- 桌面布局按视口缩放，全屏按钮收起全局导航，并尝试调用浏览器全屏。窄屏通过分区按钮切换内容。
- 图表和统计入口可下钻。详情路径按桥梁、模块、分类、具体对象最多四层组织，并提供返回入口。

主图是预渲染城市示意图与可交互 SVG 测点叠加。场景用于外形展示，尚未接入可旋转 BIM 或 GIS 服务。

### 实时监测与设备台账

当前包含 223 台演示设备。设备卡直接展示类型、编号、桥梁和状态，已关联测点的设备还显示测点名称及读数。

支持按传感器分类、桥梁和状态筛选，以及编号、类型和测点搜索，每页展示 24 台。设备档案与大屏测点、已有设备关联的预警记录互相链接。

### 数据服务 → 数据查询

- 当前覆盖巨力大桥 27 项、乐凯大桥 16 项监测属性。属性来自前端测点与监测项配置。
- 支持属性搜索、测点选择、起止时间查询、趋势图和数据表切换。
- 显示最新值、最大值、最小值与平均值，支持 CSV 导出。
- 已关联设备的属性可打开设备档案。

查询页根据当前值与所选时间范围生成 97 条演示样本。页面有演示数据标识，后台尚未存储历史时序，因此这里的曲线和 CSV 均为生成的数据。

### 系统设置

- 人员管理支持新增、查看、编辑、角色调整、密码重置和删除，保存到 SQLite。
- 当前管理员账号不可删除或修改自身账号、角色，并保护最后一个管理员。
- AI 配置支持保存服务商和模型名称，以及新增、替换、删除 API Key。
- 密钥接口仅返回是否已配置，不回传密钥原文。
- 系统版本读取后端 OpenAPI 信息，当前为 `0.1.0`，页面只读展示。

AI 问答仍使用本地知识库和打字机输出，保存 AI 配置尚不会调用外部模型。API Key 当前以明文存入本地 SQLite，适合使用测试密钥。生产使用前需要完善密钥保护和模型调用链路。

### 其他模块

桥梁管理、报警管理、评估分析、项目管理、安全评估、视频监控、监测知识库与智能问答均保留。各业务页提供当前桥梁的关联数据入口。知识库中的技术参数、图片和方案说明为演示资料。

## 数据来源与持久化范围

前端大屏、设备、测点、工单和项目展示主要读取 `js/mock-data.js`。项目管理的新增、编辑和删除当前只修改页面内存，刷新后恢复。前端演示工单操作、设备诊断提示也尚未与后端完整联通。

后端 SQLite 保存账号、AI 配置及初始化的项目、设备、监测项、报警、工单。后端存在项目 CRUD 等接口，但前端项目管理尚未调用它们，前后端业务数据尚未统一。

仍待完成的主要能力包括真实采集、历史时序查询、设备/测点/阈值的完整持久化 CRUD、统一权限与审计，以及外部 AI 模型接入。“所有可配置项支持完整 CRUD”尚未实现。

数据库默认位于启动后端时的工作目录，按本文命令运行即为 `backend/shm.db`，该文件已被 Git 忽略。已有数据库不会因修改种子数据而自动覆盖更新。

## 代码位置

- `index.html` 包含导航、页面和弹窗容器。
- `js/app.js` 管理页面、桥梁上下文、四层路径和全屏。
- `js/dashboard.js`、`js/bridge-twin.js` 管理大屏和测点交互。
- `js/data-history.js` 实现趋势查询、数据表和 CSV。
- `js/settings.js`、`js/auth-demo.js` 对接系统设置和登录。
- `js/portal.js`、`js/workorder.js` 管理项目展示、设备和工单详情。
- `js/charts.js` 为原生 Canvas 图表库，`js/ai.js` 为本地问答逻辑。
- `css/` 按页面拆分样式。
- `backend/app/` 包含数据库模型、认证和 REST 路由。
- `tools/render-bridge-city.cjs` 生成城市主图。

## 城市主图维护

日常运行直接加载 `assets/img/juli-city.webp` 和 `assets/img/lekai-city.webp`。重新生成图片需要 Node.js、Three.js `0.160.1`、`playwright-core` 和兼容的 Chrome/Chromium。

可将工具依赖安装到项目外的目录，再从项目根目录执行以下命令。

```bash
NODE_PATH=/absolute/path/to/node_modules CHROME_BIN=/absolute/path/to/chrome node tools/render-bridge-city.cjs
```

工具会覆盖两张主图并输出部分测点投影坐标。新增测点位置维护在 `js/mock-data.js` 的 `deployments` 中，修改相机或桥体后需要同步校正这些坐标。

## 检查方式

前端语法和差异空白检查可从项目根目录执行。

```bash
for file in js/*.js tools/*.cjs; do node --check "$file" || exit; done
git diff --check
```

后端语法检查在激活虚拟环境后执行。

```bash
python -m compileall -q backend/app
```

手动验收时，检查两座桥切换、测点到设备定位、四层返回路径、全屏布局、全部属性趋势、时间校验、CSV、账号权限和配置保存。当前仓库没有提交浏览器自动化测试套件。
